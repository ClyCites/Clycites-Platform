# Documentation Drift Audit

Documentation is extensive: 65 ADRs, architecture/product/security material and operational guides. It generally describes intended constraints well, but readers can easily confuse design coverage with runtime readiness.

| Drift / ambiguity                                          | Evidence                                                                                                           | Required correction                                                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Phase documentation can read as delivery evidence          | ADRs and phase operations describe complete flows; audit matrix shows partial/live gaps                            | Add implementation-status and last-verified sections linking to this audit                                     |
| Browser suite labels overstate scope                       | `test:accessibility`, `test:offline`, `test:performance` exist, but tests are fixture semantic/abort/timing smokes | Rename documentation descriptions to smoke checks and state exclusions                                         |
| Provider docs can imply readiness                          | SDK/manual boundaries exist; no approved sandbox execution occurred                                                | Label Hedera `SANDBOX_CAPABLE`, payments/SMS `MOCK_ONLY`, object storage `LOCAL_READY`                         |
| Backup model/runbook can be mistaken for recovery evidence | [backup-restore-verification.md](../operations/backup-restore-verification.md) exists; no restore executed         | Add most recent restore result, environment, RPO/RTO and evidence owner                                        |
| OpenAPI presence can be mistaken for endpoint verification | 204 paths validated; not all paths exercised                                                                       | Distinguish generated contract coverage from integration coverage                                              |
| Seeded pilot resembles operational readiness               | Seed includes supervised pilot; preflight actually returns `passed:false`                                          | State prominently that all pilot records are synthetic and blocked                                             |
| Payment/Hedera statuses risk false interpretation          | UI fixture shows completed payment and mock Hedera mode                                                            | Always display provider/network/evidence limitation; never equate submission with payment or anchor with truth |
| Local credentials are visible by design                    | `.env.example` and seed defaults are documented local-only                                                         | Keep warning; require deployment checklist proof of unique secret-manager values                               |
| Prisma generation command prerequisites                    | Root `db:generate` fails without `DATABASE_URL`                                                                    | Document that even generation loads Prisma config and needs a local/test URL                                   |
| Test documentation lacks empty-package disclosure          | DB/UI/observability scripts pass with no test files                                                                | List packages with zero tests explicitly                                                                       |

No broad documentation rewrite was made. Exact corrections should be applied alongside remediation so claims remain synchronized with executable evidence.
