## Specific Review Notes

- Cookies: production startup requires secure refresh cookies; SameSite is `lax` or `strict`. The API test rotates cookies but does not assert all flags.
- CSRF: refresh uses a cookie with SameSite and restricted CORS. No explicit synchronizer token exists; reassess if cross-site deployment requirements change.
- Finance: distinct approvers, encrypted payment identifiers and no-false-`PAID` worker behavior are tested. Real callback security is not applicable because no real payment adapter exists.
- Files/CSV: imports are size/checksum bounded, parsed strictly, and formula-prefixed trimmed values are rejected. Object access and malware scanning were not exercised.
- Public APIs: traceability is throttled and uses allowlisted serializers; tests exclude farmer IDs and private anchor payloads.
- Logs/queues: worker payload tests avoid recipient/payment details; full log-redaction fuzz coverage is absent.
- Secrets: no committed private-key/token pattern was observed in the audited surfaces. Example credentials are explicitly local-only and production validation rejects local cryptographic defaults.
